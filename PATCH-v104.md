# PATCH v104 — восстановление раздела «Акты АОСР» (2026-09-14, Эксперт)

## Диагноз (глубокий аудит)
1. **Таблица `acts` удалена из базы** (REST 404): раздел «Акты» не сохранял
   акты вообще — insert завершался ошибкой.
2. **Скрытый дефект v103**: список актов не загружался при входе в раздел —
   `ACTS` инициализирован `[]`, а загрузка из базы запускалась только при
   `ACTS === null` (то есть только после своего сохранения/удаления).
3. Прямое восстановление таблицы невозможно без DDL-доступа к базе
   (пароль Postgres / access token Supabase отсутствуют в распоряжении).

## Решение (без DDL, без правки 390-КБ index.html)
Акты хранятся как JSON-файлы в Supabase Storage: бакет `files`, папка
`acts/<team_id>/<timestamp>.json`. Storage проверен: запись/чтение/удаление
работают с текущим publishable-ключом. Синхронизация между устройствами
сохраняется (общий бакет), конкурентные конфликты исключены уникальными
именами файлов.

## Механизм доставки
Патч размещён в `supabase-config.js` (единственный маленький JS-файл,
подключаемый до основного кода). После загрузки приложения он переопределяет:
- `loadActs` — чтение списка актов из Storage (сортировка по `num`);
- `renderActs` — всегда грузит акты при входе в раздел (фикс дефекта №2);
- `actSave` — сохранение акта JSON-файлом;
- `actDel` — удаление файла акта.
Форма, нормативка (РД-11-02-2006, СП 70.13330.2012), реестр и печать акта —
без изменений, из основного кода.

## Как сделать постоянным (при наличии действующего GitHub-токена)
1. Вшить код `ActsStore` и новые `loadActs/actSave/actDel/renderActs`
   из `supabase-config.js` в `index.html` (секция «АКТЫ И ДОКУМЕНТЫ»).
2. Удалить из `index.html` realtime-подписку на таблицу `acts`
   (безвредна, но мертва).
3. Очистить `supabase-config.js` до исходных двух строк конфигурации.
