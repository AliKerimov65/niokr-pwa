# Шаблон доработок «НИОКР Команда» — реестр решений

Правило: каждая доработка по завершении получает вопрос «Внести в шаблон? Да/Нет №N»
(нумерация сквозная). «Да» — доработка становится обязательной частью приложения для всех
команд и объектов (единое PWA, наследование автоматическое). «Нет» — разовая, только для
запросившей команды.

Правило автообновляемой справки (v154): каждая новая функция/доработка ОБЯЗАТЕЛЬНО
сопровождается строкой `helpReg(...)` в реестре HELP (index.html) с номером версии —
раздел «Как работать в приложении» обновляется из этого реестра сам, без ручной правки.

### №15. Пуш-уведомления — состав обязательного функционала шаблона

1. **Подписка на устройстве:** меню ☰ → «Push-уведомления» (кнопка видна при поддержке
   Service Worker и Push API). Подписка создаётся с публичным VAPID-ключом из `index.html`
   (`VAPID_PUBLIC`) и сохраняется в таблицу `push_subs` (member, endpoint, auth, p256dh).
   Авто-возобновление подписки при входе, если разрешение уже выдано.
2. **Отправка:** клиентская функция `pushNotify(members, title, body, url)` → POST на edge-функцию
   `push-send` (сейчас развёрнута в резервном проекте Supabase `nlgxrendtkxlzisqikoj`,
   читает/чистит `push_subs` основного проекта через секреты NIOKR_SB_URL/NIOKR_SB_KEY;
   см. `EDGE-FUNCTIONS.md`). Битые подписки (404/410) удаляются автоматически.
3. **События с пушами:** сообщение в канал команды, личное сообщение, файл в чате,
   новая задача (адресату), объявление, публикация отчёта.
4. **Service Worker (`sw.js`):** обработчик `push` (показ уведомления с tag и url)
   и `notificationclick` (фокус/открытие приложения на нужном экране).
5. **Ключи:** публичный VAPID — в коде; приватный — только в секретах Supabase
   (резервная копия у владельца проекта, не в репозитории).
6. **Для новых команд/объектов:** ничего настраивать не нужно — работает из коробки;
   каждый участник включает пуши на своём устройстве через ☰.

### №19. Редактирование ФИО участника — состав обязательного функционала шаблона

1. **Поле ФИО** — первое в форме «Редактировать карточку»; ручное исправление
   (опечатки, порядок слов, регистр, отчество).
2. **Валидация:** ФИО не может быть пустым; блокировка дублей — точное совпадение
   без учёта регистра с любым существующим участником.
3. **Каскадное переименование** по ключу-имени: `members.name`,
   `team_members.member` (все команды), `wa_chats.member` (шлюзы WhatsApp/MAX).
   При переименовании самого себя обновляется локальный профиль (`me.name`) —
   перелогин не требуется.
4. **Архив неизменен:** история сообщений и подписи в ранее выгруженных актах и
   протоколах остаются под прежним ФИО (документы задним числом не переписываются).

### №20. Шапка: уведомления и онлайн — состав обязательного функционала шаблона

1. **Колокольчик 🔔 в основной шапке** (всегда на виду): состояние видно по иконке —
   обычный с красной точкой и пульсом-приглашением (выкл), подсвеченный (вкл),
   инструкция (заблокировано браузером).
2. **Активация в один тап:** первое нажатие — окно с объяснением для смартфона
   (Android/iPhone) и ПК + кнопка «Включить уведомления»; системный запрос браузера
   следует за нажатием (ограничение платформ).
3. **Автоактивация:** одноразовое автопредложение при первом входе; если разрешение
   браузера уже дано — подписка создаётся и восстанавливается сама, без нажатий;
   ручное отключение запоминается и не перезаписывается.
4. **Разблокировка:** при denied — пошаговая инструкция для iPhone / Android / ПК.
5. **Счётчик онлайн 🟢N в шапке:** число участников в сети (Supabase presence,
   реальное время); нажатие — список «Сейчас в сети» с переходом в карточки участников.

### №18. Бегущая строка протокола — состав обязательного функционала шаблона

1. Во время совещания (комната совещаний), пока панель протокола закрыта, над панелью
   управления идёт бегущая строка: метка «● ПРОТОКОЛ» (мигает) + последние реплики
   (до 6) вида «Имя: текст • …», имя окрашено в цвет говорящего.
2. Скорость прокрутки адаптируется к длине текста; обновление реплик перезапускает
   анимацию без дёрганья; появление/скрытие строки перестраивает сцену комнаты.
3. Нажатие на строку открывает панель протокола; при открытой панели строка скрыта.
4. Если распознавание речи недоступно/выключено — строка показывает состояние
   «Идёт запись протокола…» и ручные реплики.

### №21. Категории пуш-уведомлений — состав обязательного функционала шаблона

1. Экран «🔔 Уведомления» (меню ⚙ → Push-уведомления, также из окна активации):
   блок «На этом устройстве» (вкл/выкл/инструкция при блокировке) + переключатели
   категорий: 💬 чат, ✉️ личные, ✅ задачи, 📢 объявления и отчёты, 👋 вход участников.
2. Хранение: `push_prefs` (member → prefs jsonb) в резервном проекте `nlgxrendtkxlzisqikoj`;
   API — действия `prefs-get`/`prefs-set` edge-функции `push-send`. Локально — зеркало
   в localStorage (`pushCats`) и IndexedDB (`niokr-push`) для service worker.
3. Фильтрация серверная: `push-send` не отправляет категории с `prefs[kind]===false`;
   резервный фильтр в `sw.js` по IndexedDB (не показывать уведомление отключённого kind).
4. Выбор действует на все устройства участника сразу; по умолчанию всё включено;
   каждое уведомление несёт `kind` в полезной нагрузке.

### №22. Пуш «участник вошёл в приложение» — состав обязательного функционала шаблона

1. Категория `online` («👋 Вход участников»): при входе участника остальные члены
   текущей команды получают пуш «👋 ФИО в сети — Вошёл в приложение · команда».
2. Отправляет клиент вошедшего (после загрузки состава команды) — работает независимо
   от того, кто онлайн; себе не шлётся (фильтр в `pushNotify`).
3. Антиспам: один раз за сессию вкладки (перезагрузка — не вход); не чаще 1 раза в
   3 часа с устройства; если в команде нет других участников — не шлётся и лимит
   не расходуется.

### №25. Самообновляемый раздел «Как работать в приложении» — состав обязательного функционала шаблона

1. Раздел рендерится только из реестра HELP (index.html): каждая функция приложения —
   одна строка `helpReg(иконка, фон, название, описание, № версии)`; ручного HTML раздела нет.
2. Каждая новая доработка обязательно сопровождается строкой в реестре с номером версии —
   новые темы появляются в разделе автоматически у всех пользователей.
3. Авто-бейджи: «✨ новое · vN» — функции текущей версии, «обновлено · vN» — последних
   трёх версий; номер версии приложение само читает из `sw.js` (без ручного ввода).
4. Поиск по разделу (строка «🔍 Поиск по разделу…») и авто-строка актуальности
   «Актуально для версии vN · тем: M» — пересчитываются сами.
5. Для новых команд/объектов: ничего настраивать не нужно — раздел единый для всех.
